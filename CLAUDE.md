## Project Overview

This is the **flowc-console** - a web-based admin console for the flowc API Gateway (Envoy proxy-based). Built on top of the Shadcn Admin Dashboard template using React 19, TypeScript, Vite, and TanStack Router.

## Architecture

### Routing System (TanStack Router)

**File-based routing** with automatic code splitting. Routes are defined in `src/routes/`:

- Route files use special naming conventions:
  - `_authenticated/` - Layout route (prefix `_` = no path segment)
  - `route.tsx` - Layout component
  - `index.tsx` - Index route for that path
  - Protected routes nested under `_authenticated/` use the authenticated layout

- **Route generation**: `routeTree.gen.ts` is auto-generated by the Vite plugin - never edit manually

- **Navigation**: All routes have access to `search` params and `navigate` function via TanStack Router hooks

### State Management Strategy

**Three-tier state approach:**

1. **URL State** (table filters, pagination, sorting)
   - Use `useTableUrlState()` hook for tables
   - Syncs filters/pagination to URL search params
   - Enables shareable, bookmarkable table states
   - See `src/features/users/components/users-table.tsx` for reference implementation

2. **Zustand Stores** (auth, minimal global state)
   - `src/stores/auth-store.ts` - User and access token
   - Token persisted in cookies with key `'thisisjustarandomstring'`
   - Call `useAuthStore.getState().auth.reset()` to clear auth

3. **React Context** (UI preferences)
   - Theme, font, direction (RTL/LTR), layout config
   - All in `src/context/`

### API Integration Pattern

**React Query + Axios** (infrastructure ready, currently using mock data):

```typescript
// Query client configured in src/main.tsx with:
// - Auto-retry (except 401/403)
// - 10s staleTime
// - Centralized error handling
// - Session expiry handling (401 → logout + redirect)
```

**Error handling flow:**
1. Axios errors caught by `handleServerError()` in `src/lib/handle-server-error.ts`
2. 401 errors → clear auth + redirect to `/sign-in`
3. 500 errors → navigate to `/500` (prod only)
4. Toast notifications via Sonner

**To integrate real API:**
1. Create API service layer in `src/lib/api/` (e.g., `endpoints.ts`, `routes.ts`)
2. Add Axios interceptor to inject auth token from `useAuthStore`
3. Replace mock data with `useQuery`/`useMutation` hooks
4. Use React Query devtools (bottom-left in dev mode) to debug

### Data Table Pattern

**Complete CRUD table system** - use `src/features/users/` as the canonical example:

```
users/
├── components/
│   ├── users-table.tsx           # Main table with TanStack Table
│   ├── users-columns.tsx         # Column definitions
│   ├── users-action-dialog.tsx   # Create/edit form (React Hook Form + Zod)
│   ├── users-delete-dialog.tsx   # Delete confirmation
│   ├── data-table-row-actions.tsx    # Row action menu
│   └── data-table-bulk-actions.tsx   # Multi-select operations
├── data/
│   ├── schema.ts    # Zod schema + TypeScript types
│   ├── data.ts      # Enums, constants, styling configs
│   └── users.ts     # Mock data (Faker.js)
└── index.tsx        # Feature export
```

**Key features:**
- URL-synced pagination, filters, sorting
- Column visibility toggle
- Row selection with bulk actions
- Faceted filters (multi-select dropdowns)
- Search/filter toolbar
- Responsive design

**To create a new table:**
1. Copy `users/` feature folder structure
2. Define Zod schema in `data/schema.ts`
3. Create columns in `components/[name]-columns.tsx`
4. Build table in `components/[name]-table.tsx` using `useTableUrlState()`
5. Add dialogs for CRUD operations
6. Define route in `src/routes/_authenticated/[name]/`

### Form Handling

**React Hook Form + Zod validation pattern:**

```typescript
// 1. Define Zod schema
const formSchema = z.object({
  name: z.string().min(2).max(50),
})

// 2. Create form with resolver
const form = useForm<z.infer<typeof formSchema>>({
  resolver: zodResolver(formSchema),
  defaultValues: { name: '' },
})

// 3. Handle submit
function onSubmit(values: z.infer<typeof formSchema>) {
  // API call or mutation
}
```

See `src/features/settings/` for examples of auto-save forms.

## Authentication Flow

Current setup (adapt for flowc backend):

1. User signs in → receive access token
2. Store token: `useAuthStore.getState().auth.setAccessToken(token)`
3. Store user: `useAuthStore.getState().auth.setUser(user)`
4. Token automatically persisted in cookies
5. On 401 error → auto-logout + redirect to `/sign-in`

## Feature Development Pattern

When building new features for flowc console:

1. **Create feature folder:** `src/features/[feature-name]/`
2. **Define data schema:** Zod schema + TypeScript types
3. **Build components:** Use existing patterns from `users/` or `settings/`
4. **Add route:** In `src/routes/_authenticated/[feature]/`
5. **Update sidebar:** Add nav item in `sidebar-data.ts`
6. **Integrate API:** Create service in `src/lib/api/` + use React Query
